# 以原图差异驱动的视觉自检与内部迭代

2026-11-06通用口径更新：[交付评分](delivery-balanced-review.md)优先。比较用于判断基本一致与画面流畅，不要求消除所有差异；可接受的纹理/阴影/装饰/合理补全写minor，80分及底线通过即停止追完美。以下历史案例的精确金影要求不推广到所有需求；初稿后最多两轮针对性返工。

状态：active，指项目采用的Agent执行要求，不是已实现的自动审美评分器。来源：[双语古典海报案例](../cases/trueself-20261030/README.md)。适用于所有需要保留原图视觉语言的翻译；具体字效与修复技术仍需逐图验证。

## 核心问题：能读和有图层，不等于像原图

本例确实读取原图、单独去字、制作字层、合成并实际审核，旧版还经过另一Agent查看，却仍被用户指出阴影不足、字体偏平。因此不能把问题解释为“没走五阶段”，也不能把改进简化为多加一次reviewer。

旧版用单色金字与约1px偏移的实色复制表达阴影；审核认为“金色衬线和短影可接受”。原图更关键的是厚实字面、贴根暗部、向右下柔化的墙面投影。分析虽提及风格，却没有把这些区别变成足以否决初稿的对比标准。

## 为什么用户可能先发现

从反馈可确认：用户能看到原作与目标的平面感差异，并明确指出阴影。对用户实际思考过程不能读心。合理解释是：判断“像不像、厚不厚、是否贴在墙上”不需要知道图像处理参数，人可以先从整体深度和对比察觉缺口，再用“少了阴影”描述。

有记录支持的Agent失误：样式还原不足、对风格的通过标准偏宽、对比观察没有指出足够具体的视觉证据。完成偏向、对自己方案的确认倾向、沿用旧结论可能是机制假设，不当作已证明的唯一心理原因。不能声称旧审核完全没看图，也不能把计算门禁当作造成审美失败的唯一原因。

能力与责任的改进应落在可观察行为：先从源图定义要求，再拿候选寻找失败证据，不以“我用了这个效果”代替“图里实际看得出这个效果”。

## 1. 制作前：只提取本图最决定观感的特征

实际看源图的缩略、100%及必要放大区域，选出约3～5项影响最大的特征，而不是复制通用形容词。每项记录：

| 项目 | 要写的依据 |
| --- | --- |
| 源图特征 | 哪个区域、看到了什么；没有的效果记无，不清楚记不确定 |
| 目标要求 | 不依赖某段代码的视觉结果，例如“原尺寸仍有贴边暗部和柔化影尾” |
| 候选实现 | 字体/参数/资产/模型只是实现假设，不是质量证明 |
| 失效风险 | 可能平贴、字腔堵、脏晕、抢主体、行密度丢失或损害语义 |

本例应关注：字面分量、接触暗边与柔投影的区别、暖金亮度关系、窄栏行密度。不能只写“金色粗衬线＋阴影”。分析投影时区分方向、与字面的距离、软硬、覆盖与渐弱，不凭低清图片捏造精确源参数。

脚本选路：常规字体、精确文案、可表达的暗边/阴影/轻明暗先评估可控工具；现有字体和效果难以表达的造型、复杂材质或装饰融合才评估imagegen/设计资产。当前imagegen无原图/蒙版输入，不能冒称精准去字。选路服务视觉结果，不能反过来把结果限制在已有工具的最简单效果上。

## 2. 合成后：先找缺口，再判断是否可交付

源图、候选以相同画布尺寸并排，必要时增加旧版，避免不同倍率夸大或掩盖效果。实际打开所需证据后记录比较，不只填写“style=true”。

- 全图缩略：第一眼的力度、重心、层级和主体竞争是否改变？是否只剩颜色相似？
- 100%原尺寸：源图重要效果在目标中是否仍能感知？投影/描边是否缩小后消失？小字真的可读吗？
- 放大局部：为什么不一致？是字重、贴边暗部、投影、字距、明暗，还是背景接缝？放大用于定位，不能用放大后明显冒充原尺寸有效。
- 单独字层：组成和缺字/边缘问题可见；最终效果仍需在真实底图上判断，棋盘格不能代替合成。

每个关键特征写“源图观察→候选差异→通过/失败/不确定→实际证据文件与区域”。已存在明显差异却只写“可以接受”不构成通过依据；解释字体语言差异，也不能自动豁免可修复的字重或投影缺口。

至少主动问一次：**如果这是别人提交给我的版本，我会指出什么不像原图？** 提出由源图支持、能够失败的问题，例如：本例“字是否仍像平贴？贴边暗部/软影是否只变成硬黑描边？”源图无阴影时应问“是否错误添加了阴影”，不能把本次修订参数推广为一律加厚、加大投影。

这些比较可写入现有review的notes/global_notes/stage_notes，或单独的版本绑定比较记录。不得擅自向CLI配置添加未支持字段；现有质量合同只验证证据结构、哈希和部分像素约束，不能自动执行此审美判断。

## 3. 独立复核：要求标准独立，而不只身份独立

需要另一审核者时，让其先从源图提出关键视觉要求，再对照候选；首次视觉判断尽量不以制作方的“效果已完成”或旧pass引导。必要事实如语义/保护范围可以提供。之后合并证据、讨论差异。

问审核者具体缺口、最弱区域和反例，不能只问“能否通过”。另一人已看图、哈希正确仍可能共享偏宽的标准；不靠增加Agent数量取代改进问题与证据。真实独立身份如实记，制作方自审不能冒充独立。

## 4. 自主循环：把必要试错留在首次交付之前

一轮是：**观察到具体缺陷→提出可验证改动假设→改相关层→输出新候选→同尺度复审→检查退化**。

- 用户未提醒也应主动处理已观察问题；不等待用户替Agent指出可见漏项。
- 背景已通过、问题在字效时复用背景，不重擦整图。文字/字效变化只返工文字与合成；人物、商标等保护要求始终保留。
- 每轮调整有依据的变量，记录改动前后是否实际改善，并反查新缺陷：字腔堵塞、粘连、裁切、双轮廓、脏晕、失去主体重心、语义变化。
- 无新缺陷且本图关键目标有实际证据支持时停止制作、提交最佳版本；不为完成固定轮数制造候选，也不无依据反复生图。
- 连续两轮同因无可辨改善、参数相互抵消或缺可靠能力时，停止无效搜索，换路线或保留最佳版并说明具体限制。技术/付费权限不足按当前授权处理，不能为完成循环擅自外调。
- 所有变化重新绑定实际输入/输出哈希和审核，旧失败与旧结论保留；没有改变的背景可以引用先前实际审核，但需确认文件未变。

目标是**首次交付前发现并修复可见问题**，不是声称第一张内部候选必完美，也不是以用户反馈代替自检。次数或时间上限仅防止无界搜索，不是达标证据。

## 5. 反馈与记忆的准确边界

“好一些”只支持所述版本的相对改善，不等于完全满意，不得倒填旧审核或称新风格为长期偏好。保存原话、展示的版本哈希、具体认可/否定范围和仍有差异。记录用户如何提出问题与Agent如何漏检时，把事实、解释假设和改进动作分开。

可复用的是差异检查、阶段回溯和证据闭环；本例的金色、偏移、模糊、字重不是所有图片的默认值。新任务仍从新源图开始判断。
