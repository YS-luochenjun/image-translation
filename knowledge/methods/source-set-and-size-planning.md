# 原图图组、目标语言与尺寸规划

状态：active。适用于图片翻译接单、批量翻译及尺寸适配；先确定交付集合，再制作。用户2026-11-06确认：提供的五张长方竖图本身就是一组，六种语言各交一整组，共30张；不能把每张来源再扩成七张。

## 先确定是哪一种集合

| 需求依据 | 模式与计数 | 制作方式 |
| --- | --- | --- |
| 已提供完整图组，只要求翻译这些图 | `provided_source_set`；实际来源数×去重目标语言数 | 逐来源保留明确规格和构图，每种语言包含完整来源集合 |
| 明确要求一长三方三竖，且提供真实七成员参考 | `reference_seven_set`；独立创意×语言×七成员 | 冻结参考资源及范围依据，逐成员适配 |
| 正文明确七种构图/尺寸，但没有七参考资源 | `explicit_members` | 显式列成员ID和尺寸，不伪造参考资源 |
| 明确给出尺寸清单 | `explicit_sizes` | 依尺寸清单展开；不要再叠加其他默认集合 |
| 只有“长方竖图”分类、quantity或附件数量 | 范围尚未确定 | 结合正文与真实图组核实，不直接套七成员 |

`quantity=1`可能指一个需求或一组，不等于一张原图。附件数决定来源集合的前提是它们确实都是需要翻译的来源，而非装饰素材或参考证据。

五来源×六语言的完整性要按矩阵核对：每个 `(source_id, language, member_id)` 恰好一张；每种语言五个来源齐全。30个文件或30条记录不能抵消某语言漏图、另一语言重复图。语言别名先按接入合同规范化，保留原始字段，去重后计数；未知语言不能猜。

## 尺寸优先级与实际适配

1. 当前明确需求及已经接受的规格。
2. 有当前可核证据的同组同类型已交付规格。
3. 项目默认；仅用于缺规格的待制作或待适配成员。

机器规则见[尺寸策略](../../docs/material-size-policy.json)。`image`没有无条件七成员默认；`provided_source_set`保留各源的明确native规格。大按钮独立处理：无明确规格时横/方源采用300×250、336×280，竖源采用300×600，并遵守当前官方尺寸白名单、PNG/JPEG及150KiB限制。图片资源上限和平台限制以当前正式合同为准，不把历史快照当永久许可。

尺寸变化先区分裁剪、留白与重排：只裁无信息背景；保留文字、身份、动作及条件。跨度较大的方竖图重排独立主体与字层，不拉伸整张广告，不重复贴图凑张数。只有明确的七成员任务才以完整大横母版派生不同取景的七张；已提供的五张整组无需重造七成员母版。

运行 `material-size-plan SPEC.json`冻结来源、语言、成员和尺寸，再用`material-size-validate SPEC.json`核真实文件。技术校验不替代看图；输出SHA变化后须重新审核。

## 复用与交付

先核当前来源SHA与旧成果来源、译文和规格是否相同，再实际看图复核候选。相同合格字节可以复用，不为追更高分重新制作；用户认可范围、旧审核和当前复核分别保存。跨需求复用内容不等于复用旧发布操作ID、绑定关系或权限证据。

按[交付评分与取舍](delivery-balanced-review.md)逐成员审核：80分及全部底线通过就交付，初稿后最多两轮局部修正。允许自然补全和局部差异；金额、条件、核心身份、完整译文和可读性不能用高总分抵消。失败只影响有关成员或共用源组，独立合格成员继续。整组完成还需全部明确成员的正式绑定及fresh下载核验。
