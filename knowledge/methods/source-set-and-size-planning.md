# 原图图组、目标语言与尺寸规划

状态：active。按用户最新交付范围，已有版式的图组按实际待翻成员交付，每套可为5、7、8、10张等，多套分别制作和提交。独立原图需要派生版式且未指定规格时，默认1长、3方、3竖。先确定来源×去重语言×成员矩阵，再制作。

## 先确定是哪一种集合

| 需求依据 | 模式与计数 | 制作方式 |
| --- | --- | --- |
| 长方竖图只给原图创意，没有明确特殊交付范围 | `standard_seven_set`（默认）；逐来源去重语言×7成员后求和 | 每个独立创意派生1长3方3竖，单个需求可以包含多个独立来源 |
| 已提供可识别的同组版式成员 | `provided_source_set`与`provided_set_scope=explicit_source_only`；实际图组×该组语言×真实待翻成员 | 核对创意、版式、来源及尺寸，逐组保留成员清单 |
| 用户明确只翻所供原图或指定非标准成员 | `provided_source_set`并记录`provided_set_scope=explicit_source_only`及`scope_basis`，或使用显式成员模式 | 保留明确用户依据，主控自己的“每附件只做一张”判断不构成例外 |
| 明确要求一长三方三竖，且提供真实七成员参考 | `reference_seven_set`；独立创意×语言×七成员 | 冻结参考资源及范围依据，逐成员适配 |
| 正文明确七种构图/尺寸，但没有七参考资源 | `explicit_members` | 显式列成员ID和尺寸，不伪造参考资源 |
| 明确给出尺寸清单 | `explicit_sizes` | 依尺寸清单展开；不要再叠加其他默认集合 |
| 只有“长方竖图”分类，已有真实独立原图与目标语言 | 默认标准七成员 | quantity或当前附件数不能把一套缩为1、2、3张；无原图/语种仍保留对应缺口 |

`quantity=1` 可能指一个需求或一组。逐张看创意、主体、核心文案和版式，结合文件名连续编号、原素材归属和尺寸确认成员。已有目标语成品或参考图按正文和来源证据确定用途。独立原图按需要派生版式。各来源语种不一致时逐来源求和。

下载后按实际文件SHA核完全重复附件；用途与要求一致时合并制作来源，保留全部附件ID的别名映射。相近构图不能自动合并，年龄、数字和条件都要逐图识读。SHE-031的六附件只有三个唯一SHA，因此三来源×十四语=42张，证据见[本轮批次案例](../cases/she-batch-20261111/README.md)。

每个 `(source_id, language, member_id)` 恰好一张。已供图组按计划中的实际角色和数量核对，默认派生套才要求1长、3方、3竖。语言别名按接入合同规范化，保留原始字段并去重。

## 尺寸优先级与实际适配

1. 当前明确需求及已经接受的规格。
2. 有当前可核证据的同组同类型已交付规格。
3. 项目默认；仅用于缺规格的待制作或待适配成员。

机器规则见[尺寸策略](../../docs/material-size-policy.json)。默认派生套 `standard_seven_set` 使用1张1200×628、3张1200×1200、3张960×1200。按实际图组翻译时在 `scope_basis` 记录用户授权、归组依据和范围，使用 `provided_set_scope=explicit_source_only` 编入实际成员。每套独立保存清单，多套另存整单矩阵供终核。大按钮无明确规格时横/方源采用300×250、336×280，竖源300×600，遵守当前官方尺寸白名单、PNG/JPEG及150KiB限制。

尺寸变化先区分裁剪、留白与重排：只裁无信息背景；保留文字、身份、动作及条件。跨度较大的方竖图重排独立主体与字层，不拉伸整张广告，不重复贴图凑张数。标准套以足够清晰的母版派生不同取景的七张；用户明确的特殊原图范围按其依据执行。合格现有成员保留，缺项持续补齐，未齐不得报告整套完成。

运行 `material-size-plan SPEC.json`冻结来源、语言、成员和尺寸，再用`material-size-validate SPEC.json`核真实文件。技术校验不替代看图；输出SHA变化后须重新审核。

清晰摄影底图的PNG超过字节上限时，在当前合同允许JPEG的前提下评估高质量JPEG；保留清晰背景，避免为压缩而整片模糊或遮暗。实际编码后的像素、格式、字节、细字/描边和主体都须重核，审核绑定最终编码文件SHA。SHE-032的双尺寸JPEG符合当次150KiB限制，不把该格式、压缩参数或上限推广成其他平台的固定合同。

## 复用与交付

先核当前来源SHA与旧成果来源、译文和规格是否相同，再实际看图复核候选。相同合格字节可以复用，不为追更高分重新制作；用户认可范围、旧审核和当前复核分别保存。跨需求复用内容不等于复用旧发布操作ID、绑定关系或权限证据。

按[交付评分与取舍](delivery-balanced-review.md)逐成员审核：80分及全部底线通过就交付，有可行改进路线时继续局部修正，不设固定次数。允许自然补全和局部差异；金额、条件、核心身份、完整译文和可读性不能用高总分抵消。失败只影响有关成员或共用源组，独立合格成员继续。整组完成还需全部明确成员的正式绑定及fresh下载核验。
