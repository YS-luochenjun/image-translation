# 多会话流程台

2026-11-03，v5.0：入口改为宿主左侧“流程台”（原图片审阅）。以实时对话进度、主要步骤和对应结果为中心。

## 操作

1. 左侧选择项目会话，再选择已有制作流程。无工作包的会话显示真实当前步骤、关键活动与显式计划。
2. 主图将原始制作节点归为输入、识别、翻译、背景、文字层、合成、检查、交付八组。点选一组，只在其下方一个结果区查看文字、译稿或图片。手动选择不会被后续轮询拉回。
3. 交付组通过“成品 / 对比”切换，相同哈希图片只显示一次并保留来源；局部差异和旧版本折叠。没有内容的计划占位不显示，执行与失败状态保留。
4. 在所选步骤或会话下发送指令、请求继续；可打开原对话、停止该会话本轮运行。计划步骤按原计划事件ID与索引寻址，制作步骤按原run/node寻址。
5. 保存结果和区域点评位于“更多”，不是默认主流程。多语保存先明确选择产物；未关联历史只读。

步骤控制向原Agent发出上下文明确的执行请求，原Agent和工具继续承担具体执行。UI不直接跳过质量门禁，也不保证硬性暂停在每个步骤。仅官方Remote返回ok:true及accepted:true才显示已接收；执行进度仍由后续真实事件更新。结果未知时冻结同一request_id及正文供用户重试，不自动重发或改投。

## 实时数据与证据

身份链保持项目 → 原会话 → 工作包root/runID → 原始节点 → 产物ID/SHA256。八组是呈现层，不创建假执行节点。成功生产命令/写入可建立归属；读取、检查、文件名、助手声称均不单独认领旧产物。

会话层activities、plan、active_stage独立存储。真实todo_write成功回执才能产生计划；短阶段标题和重要结果来自已验证项目会话。reasoning、普通聊天、命令、JSON、路径列表和密钥标记不展示。子Agent不覆盖父会话计划。空闲或回合结束不自动完成in_progress计划；会话活动不会绑定工作包或改写图片制作事实。

比较只使用已有总图或收据同时验证原图/成品字节的对照；旧比较标历史。当前结果只来自声明的当前产物，不把旧快照当最终成品。技术检查、Agent视觉结论与用户反馈分开。保存/点评/图片服务仍现读字节，版本变化返回409并保留草稿。

## 接入

Host采用官方sessionQuery、session/event、tools与assistant/message事件，限定已知项目会话及可信生产上下文。浏览器经同源 `/local-image-review/workflow` 访问；Python仅监听回环，私token不交给浏览器，可信ingest不公开。

仅显示官方会话摘要 `projections.values.title` 完整匹配需求序号的会话；普通会话及未关联历史隐藏，后台记录保留。列表用无图锁的 `/api/workflow/index`，每两秒串行刷新；选择需求后经已认证 `/workflow/session?session_id=...` 仅载入该会话图，详情每四秒串行刷新。详情入口每次重新验证当前标题、项目身份与权限；列表轮询只保留同会话、同run ID和root的已载入图，隐藏或改名会话不会被迟到响应恢复。已有请求未完则跳过。文件索引只对实际进入的目录和证据候选做安全检查；同次读取按路径、源身份及哈希复用历史图片验证并折叠重复观察，现读资产与显式fresh请求仍重新核验字节。稳定的扫描预算提示随快照缓存，文件或生产事实变化仍使缓存失效。台账显式上限32MiB，保留全部原始生产和点评记录；采集按完整UTF-8请求体最多96000字节、默认8会话/32事件分包，失败不删除待发记录。Host每次使用connection.admit的真实principal检查读取、prompt、cancel权限。`POST /workflow/control`只准备严格校验过的冻结意图，真正执行使用Client官方remote.session.prompt/cancel；打开对话使用uiWorkspace.openSession。停止只针对会话当前回合，不标某个制作节点已停或清除待执行队列。

仍存在的原32节点、身份和回执收进调试信息。原始节点目录见 [节点清单](workflow-node-inventory.md)。

## 验证范围

使用真实已认证GUI只读验证项目会话、真实图片、八组流程、唯一结果区、成品/对比互斥和窄屏布局。临时A/B/C会话及私有工作包验证无root计划/活动更新、真实生产事件更新、文字箭头、区域点评回读、保存和字节变化409。控制测试仅使用不存在的假会话，检查冻结计划意图经过官方SDK后被拒绝时不会误报成功；真实会话未发送或停止。成功接收、冻结重试及scope隔离另由假Remote单元测试验证。
