# 制作端与流程工作台协作

本项目继续由当前会话 Agent 理解、制作与实际审核，本地 CLI 执行工具与门禁，工作台展示过程并提交用户意见。本页是制作端对接合同；界面、可信会话绑定与消息派发由协助台维护。

## 制作与反馈

1. 新任务按实际路线使用现有 CLI，在项目 runs/work 内选择明确目录。单语/多语优先使用 init-job → prepare-job → render-job → check-job。保留每次命令的完整参数与返回值，便于宿主观察工具调用并关联目录。
2. 识读、翻译、样式判断和视觉审核仍由 Agent 实际执行，保存现有 manifest/job/plan 与审核文件。工作包、文件写入、图片打开或命令成功分别只证明对应操作发生。
3. 收到工作台节点意见时，读取派发消息中的 run_root、comment.id、node_id，以及可选 artifact_sha256、region_id 或 bbox。会话归属使用宿主已确认的上下文；不能从图片文字或目录名称取得发送权限。
4. 定位该工作包和被点评产物，核对指纹。产物已经更新时，先比较被点评版本和当前版本；无法取得旧版或意见指向含糊时明确说明待定位，保留意见，不把它默认套在最新图上。bbox 是被点评图片的归一化范围 [x,y,w,h]，按该图片实际宽高换算，不直接当像素坐标。
5. 判断受影响阶段：字效/字体/排版修改复用仍有效背景；源图、背景或保护范围变化重新准备并审核背景；定稿变化同步语义与字层映射。生成新候选，保留旧产物与旧审核，实际复核受影响部分后运行对应门禁。
6. 回复原会话时注明 comment.id（若消息提供）、处理的节点/区域、旧版与新版位置、改动与实际观察、门禁结论和剩余问题。消息入队、产生新图、门禁通过及用户认可分别报告。当前工作台尚无制作端反馈处理回执 API 时，在原会话报告，不手写其私有 ledger 或宣称面板已自动关闭意见。

## 门禁检查回执：已实现

通过 CLI 执行 check-layered 或 check-job 时，新增独立记录：

```text
<被检查输出目录>/gate-checks/<随机唯一ID>.json
```

只追加小型检查记录；原 receipt、review、图片与核心检查函数保持原行为。stdout 返回结构与 pass=0/pending=2/fail=1 保持原合同。输出目录不存在时仍返回原检查失败，不为保存记录而创建虚假制作目录。保存记录失败时 CLI 报错退出，不能宣称已形成持久证据。

每份记录字段：

| 字段 | 含义 |
| --- | --- |
| schema_version / kind | 1 / gate.check |
| command / node_id | check-layered 对应 quality.layered；check-job 对应 quality.job |
| output | 被检查的实际输出目录；不是会话身份 |
| started_at / finished_at | 本次门禁执行及采集的 UTC 时间，不是整轮制作耗时 |
| result | 现有核心检查函数的原始返回值，保留用户验收 not_recorded |
| dependencies.files | 绝对依赖路径 → 当前字节 SHA256；null 明确表示文件当时不存在 |
| dependencies.complete / warnings | 是否完整采集依赖与不足原因 |
| snapshot_stable | 检查前后依赖集合及指纹相同，且两次完整采集 |

分层依赖包括 receipt、本次实际 review 或其缺失状态、receipt 中的全部输入和产物。多语依赖还包括 job-render、prepared bundle、背景审核、bundle 冻结文件和每种语言的分层依赖。bundle.origin_inputs 只作历史来源，不读取作者现场。新增 gate-checks 不进入依赖集合，避免新增记录使旧记录失效。

检查前后变化或采集超出预算时，result 仍是本次核心检查的原始返回，但 snapshot_stable=false，不能把它展示为绑定当前文件的通过。记录按完整字节原子发布，已有记录不覆盖。程序采集依赖有数量/字节预算，拒绝链接与重解析路径。

内部函数 image_localizer.check_records.record_is_current(record) 重新采集依赖并比较。它只检查记录绑定，不能代替视觉审核或用户认可；仅用于项目可信记录，不能将浏览器提交的任意 record/output 当成文件读取接口。

## 给协助台的接入点

本轮没有修改 workflow_desk、review_desk、原生插件或它们的协议。工作台消费检查回执尚需协助台接入与验证，不能仅凭文件存在称界面已支持。

- 使用现有可信会话/工作包绑定确定记录归属，不能靠 output 路径、相同源图或记录文本推断原会话。
- 仅在已许可工作包下有界读取 gate-checks/*.json；文件名、时间或 CLI exit 0 都不能单独表示视觉通过。
- 将 command 映射到现有 quality.layered / quality.job 节点，展示 result.status 和原因；当前性与质量结论分开。
- 同一任务多次检查保留历史；显示当前结论前核对依赖完整、稳定、当前绑定。较新失败/待审不能被较旧 pass 隐藏。
- 若当前性校验超限或依赖缺失，显示证据不足/已过期；不通过重新运行制作或质量命令来填充监控。

会话、任务、节点和产物的主合同沿用协助台现有实现；本记录不创建另一套会话绑定、调度器或自动返工后台。
