# 单张图片工作流

默认先应用[交付评分](../../knowledge/methods/delivery-balanced-review.md)：画面流畅、基本一致，允许自然补全与非核心差异，不逐像素追完美；≥80且底线通过即交付，初稿后最多两轮局部返工。本页“保真/差异/缺陷”按此口径区分minor与阻断问题。

路径按项目相对路径理解，RUN 替换为 runs/ID。命令成功只说明技术步骤完成；基础 CLI 为矩形横排 solid/clean_plate。常见增强操作优先用 [配置分层工具](../../docs/layered-tools.md)：prepare-layered生成背景并实际审看，render-layered完成独立字层/素材合成，check-layered校验实际审核。文字/位置变化复用背景、另建渲染版本；source/背景/保护范围变化重新prepare。复杂艺术字优先评估模型或设计工具生成独立资产，再用配置合成；复杂摄影擦字优先真正原图编辑能力。不要每图重写相同prepare/typeset/finalize脚本。仍无自动识字、弧形/透视设计或无人值守视觉审核。执行前读 [知识目录](../../knowledge/README.md)，按 [内容路由](../../knowledge/methods/content-routing.md) 和 [文字构图](../../knowledge/methods/typography-composition.md) 选择方法。

## 推荐的任务级入口

分阶段单语或多语新任务优先按[原生观感任务指南](../../docs/native-workflow.md)：init-job→各语言packet/语义与源图视觉要求→prepare-job→实际背景审核→render-job→逐语言实际比较/返工→check-job。所有目标区域映射实际rows/textassets；定稿与画布/语言/源哈希一致，保留区域自动并入共享像素保护。prepare后不得跳过背景审核；低层消费任务计划也受此门禁。字效和底图以需求选择，不将样例金影参数当默认。

背景、字体、素材与语义快照可复现，旧目录不覆盖。新目录是新的技术回执和空审核；不得复制历史pass。外观只改字层时可按分层工具复用相同背景；最终用当前源/目标原尺寸和局部找反例，比较模板具体完成后才通过。compare与benchmark只生成辅助证据，不自动识别审美缺陷。

## 基础入口初始化

```text
python bin/it.py doctor
python bin/it.py init SOURCE --target zh-CN --run runs/ID
python bin/it.py packet runs/ID
```

doctor 区分依赖/配置与真实能力。init 保留原图，按EXIF方向保存规范化 source.png；source.sha256 绑定该PNG，original_sha256 绑定原输入。坐标使用规范化画布；宿主实际打开源图确认可看，不把工作包生成当识字完成。

## 1. 语义与样式提取

使用 [解析](../prompts/analyze.md) 和 [翻译](../prompts/translate.md) 提示词。全图确认读序，100%及必要放大局部识读全部文字实例，重复位置分别登记；填写 manifest 的 regions、protected_regions、analysis、glossary。低于0.9的识读须真实复核后填 recognition_verified，不凭上下文补字；无法辨认登记 unresolved，未解决不标 complete。

记录样式计划或等价阶段说明：容器轮廓、文字层级、字重/黑白面积、宽高比、行宽与字距、弧度/透视、材质光照和视觉张力。分开源图事实与设计推断；翻译/艺术改写明确标识，不增加原文没有的承诺或对象。行宽和容器一起设计，不强拉字，不把上长下短当普适规则。

按 [差异驱动自检](../../knowledge/methods/visual-fidelity-self-review.md) 为本图选3～5项最决定观感的源图特征，写源图证据、目标视觉要求和可能失败处。区分“效果已编码”和“原尺寸实际有效”，不要只记录金色/粗体/阴影等名称；没有的效果不补，不确定的效果不捏造精确参数。

## 2. 背景单独去字与审核

使用 [修复提示词](../prompts/repair.md)。均匀底色可 solid；渐变容器可按足够依据做源像素/矢量局部重建；复杂摄影/人物的身份与核心结构优先可靠像素或真正编辑；普通纹理与非身份细节可依据观察近似补全或合理重排，以交付评分验收，不因缺精确底图自动停工。按区域选路，不能一律把复杂图判只能外部处理。

增强路线先输出无目标字底图、编辑范围/蒙版及方法/哈希，实际打开对照检查残字、接缝、容器边缘、高光与保护对象。背景未通过先修背景，不靠新字覆盖缺陷。基础 CLI 接收同尺寸本地 clean plate，不自动拉伸错位文件；增强产物如何接入以实际实现为准。

functions.image_gen 当前只有文字输入，不能编辑原图或蒙版。可在当前用户授权范围内生成设计参考，逐字核查且明确是参考；次数和费用遵循当前授权，未知授权时不自动调用付费工具，个案授权不能推成永久授权。可修问题使用剩余两轮机会；只有缺真实原文/身份依据、权限或仍无合格路线时挂起关联成员。

## 3. 独立透明目标字层

按样式计划选择脚本、矢量/设计工具或模型辅助路线，不一律脚本排字；基础 CLI 不自动识别弧形，不实现通用透视/竖排/RTL。保存独立 RGBA 字层、实际字体/布局/效果参数和透明层预览，真实查看缺字、字距、轮廓、曲线与文本准确性。字层存在不等于审核完成。

## 4. 合成

基础路线：

```text
python bin/it.py validate runs/ID
python bin/it.py render runs/ID
```

使用底图时渲染加 `--clean-background PATH`。基础渲染内部会修背景并排字，因此不能仅凭命令或其透明层输出声称已完成独立阶段审核。增强路线由 Agent 额外保存并审看阶段产物，不擅自给 manifest 添加未实现字段。

合成后检查文字与容器的行宽比例、留白、光照和重心。保留主体、商标、人物和非目标图形；像素差异统计只作辅助。读实际输入/字体/输出/底图哈希、字号、溢出及警告。最小可读字号放不下时调整布局或路线，不能无限缩小。

## 5. 全图适配审核与门禁

```text
python bin/it.py review-packet runs/ID
```

按 [审核提示词](../prompts/review.md) 依次看全图缩略、100%原尺寸及必要放大局部。缩略检查层级、张力与整体协调；100%检查实际可读；放大检查缺字、残字、描边、接缝、裁切。底图和字层也必须独立审看并记录具体文件/区域/观察，不凭 quality 文件反推已看图。

在出结论前，源图与候选以相同尺寸并排，逐项找关键特征的缺口，并指出最弱区域。需要独立复核时先让其从源图提出要求，再看制作说明和旧pass；另一身份并不能替代严格判据。

按命令真实返回路径填写当前 review.json：绑定 manifest/output SHA256、真实 reviewer 与 self/independent、全部区域五项检查、全局检查、notes 和 issues。advisories 实际逐项核对后才填 reviewed。

```text
python bin/it.py quality runs/ID
```

quality 核验证据合同，不能证明审核真实。缺证据/能力保持 pending；明确缺陷、过期哈希、区域漏项、major/critical或未解决疑点阻断 pass。透明字层或五阶段文件存在不能自动放行。

## 返工与报告

自主闭环：已观察缺陷→改动假设→相关层新候选→同尺度复审→检查退化。主动处理发现的缺口，不等待用户教Agent逐项指出。首次交付前可有必要内部候选，但不为凑轮数反复生成。背景未变且字效有问题时复用已有背景，不重擦整图。

按失败阶段回溯，一次调整有依据的变量；产物变化重算哈希并重审受影响阶段。历史候选、失败 run 与旧审核保留，不换哈希套旧结论、不把旧 pass 自动升级到新要求。连续两轮同因无改善时说明能力/输入缺口，换路线或等待证据，避免反复猜图。

分别报告技术步骤/实际产物、Agent质量与身份、具体未解决问题、用户验收。没有反馈写待用户验收；用户只认可相对改善就不能称完全通过。完整阶段合同见 [分层方法](../../knowledge/methods/layered-localization.md)。

## 与流程工作台协作

收到节点点评或区域返工消息时，按[制作端协作合同](../../docs/workflow-production-integration.md)核对工作包、产物版本与意见范围，处理受影响阶段，再向原会话报告新产物和复核结论。CLI 的 check-layered/check-job 会追加独立门禁回执，供工作台接入；核心检查函数仍只返回结果，工作台显示与会话派发状态以实际宿主能力为准。
